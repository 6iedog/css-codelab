现代 CSS / 包含

CSS 包含（contain）

contain 不改变任何外观，它只做一件事：告诉浏览器「这个盒子里外互不影响」。代价是有些以前默认成立的规则会失效。下面每一块都能现场开关，看它到底改变了什么。

速查：四种类型各自隔离什么

值 隔离的东西 能看见的副作用
layout 里外的布局互不影响 变成 BFC、包含块、层叠上下文；外边距不再穿透
paint 绘制范围 溢出内容被裁在 padding 边；同样变成 BFC、包含块、层叠上下文
size 尺寸 尺寸按「没有子元素」来算，高度可能直接塌成 0
style 计数器与引号 不做样式作用域，别当 Shadow DOM 用
content layout + paint + style 不含 size，可以放心大范围用
strict 四种全开 包含 size，必须自己给尺寸，否则塌成 0

所有演示共用的开关机制

下面每块的结构都一样：一个复选框 + 标签 + 舞台。勾选时用兄弟选择器把 contain加到目标元素上，取消勾选就自动回到没有包含的状态——所以你能看到同一个盒子「前 / 后」的差别。

/* 结构：input[type=checkbox] + label + .stage > .target */
#t-paint:checked ~ .stage .target {
    contain: paint;   /* 勾选才生效，取消自动失效 */
}

layout · 布局隔离

layout 做的是「把这块从文档流里划出去」：元素成为独立的格式化上下文，同时变成后代 absolute / fixed 的包含块，并自己开一层层叠上下文。外观一点不变，变的是原来默认成立的那些约定。下面两个案例分别踩中其中一条。

浮动不会从父盒子里逃出去

父盒子只有虚线框和内边距，没写 overflow，也没写 height。关掉时浮动元素会溢出到虚线下面——父盒子的高度只算了右边这段文字。

float
120px 我是父盒子里的一段普通文字。浮动元素高 120px，关掉开关时它会从虚线框底部冒出去。

打开后 layout 让父盒子成为独立的格式化上下文（BFC），浮动的 120px 被算进高度，虚线框把浮动包住了。

关键 CSS 
.float-el {
    float: left;
    width: 78px;
    height: 120px;         /* 浮动元素，不占父盒高度 */
}

.float-host {              /* 父盒：没写 overflow，也没写 height */
    padding: 0.5rem 0.6rem;
    contain: layout;      /* ← 变成独立格式化上下文，包住浮动 */
}

绝对定位子元素换了参照物

右上角那个小标签是 position: absolute。关掉时它贴着整个演示块跑，因为中间的父盒子没有定位属性；打开后父盒子成了包含块，标签才回到虚线框里。

absolute 关掉开关时，标签会跳到这个演示块的最右上角；打开时它才会回到我这条虚线框里。

layout 和 paint 都会让元素成为 absolute / fixed 后代的包含块。这条最容易被忽略：给容器加上 contain，里面原本贴着页面角落的弹出层会突然换位置。

关键 CSS 
.abs-el {
    position: absolute;
    top: 0.5rem;
    right: 0.5rem;         /* 相对「最近的包含块」定位 */
}

.abs-host {
    contain: layout;      /* ← 自己就成了那个包含块 */
}

paint · 绘制裁剪

条纹块高 120px，父盒子只有 62px 的内容高度。关掉时条纹会一直画到虚线框外面去。

我高 120px，父盒子只有 62px

打开后 paint 把绘制裁到 padding 边，超出的部分压根不画。它同样会创建包含块和层叠上下文，所以和 layout 的区别只在于「裁不裁」——content 就是这两者加上 style。

关键 CSS 
.paint-host {
    height: 78px;          /* 扣掉 padding，内容区只有 62px */
    contain: paint;       /* ← 超出 padding 边的一律不绘制 */
}

.spill {
    height: 120px;         /* 多出来的 58px 直接看不见 */
}

size · 尺寸不再听内容的话

这个盒子里有一个 110px 高的方块，父盒子没写任何高度，尺寸完全由内容撑开。

我高 110px，是父盒子唯一的内容

打开后 size 让浏览器按「这个元素没有子元素」来算尺寸，高度立刻塌成 0，只留下两条内边距；方块并没有消失，它只是溢出了这个零高度的盒子——因为这里没有 paint 去裁它。

所以单独用 size 几乎没有性能收益，还会把版面搞塌，必须配 contain-intrinsic-size给一个占位尺寸。这也就是 strict 比 content 危险的原因：strict 含size，content 特意不含。

关键 CSS 
.size-host {
    contain: size;        /* ← 尺寸按「没有子元素」算，高度塌成 0 */
}

.size-inner {
    height: 110px;         /* 元素还在，只是溢出了零高度父盒 */
}

/* 真实项目里必须补上占位尺寸，否则等于把版面搞塌 */
.size-host-fixed {
    contain: size;
    contain-intrinsic-size: 160px;
}

style · 计数器被关在盒子里

序号来自 counter-increment。计数器不归某个 li 所有，它是整棵列表共享的一个变量。第二条里那个小标签自己也写了一次 counter-increment: step，同一个计数器被 +1 了两次——这就是「内部计数」。

  1. 第一条
  2. 第二条，里面有一次内部计数
  3. 第三条
  4. 第四条

关掉时后面两条会被顶成 4、5；打开后内部那次 increment 只作用在自己的作用域，外面继续是 1、2、3、4。任何后代元素都能改这个计数器，所以才需要 containment 把作用域切断。注意它只隔离计数器（以及引号），不隔离选择器，这不是 Shadow DOM。

同一个计数器 step，第二条内部多了一次 +1

关闭
1 2 内部 +1 4 5

这次 +1 泄漏到外面，第 3、4 项被顶成 4、5

打开
1 2 内部 +1 3 4

+1 被关在虚线框里，外面照常 3、4

关键 CSS 
.num-list {
    counter-reset: step;   /* 计数器挂在列表上，子树共享 */
}

.num-list > li::before {
    counter-increment: step;
    content: counter(step);
}

.leak::before {            /* 第二条里的第二次 +1 */
    content: "内部 +1";
    counter-increment: step;
}

.cnt-scope {
    contain: style;       /* ← 这次 +1 不再往外传 */
}

container-type · 容器查询的底座

拖动虚线框右下角改它的宽度。里面这张卡片是按容器宽度换布局的，跟浏览器窗口无关。

40px 这张卡片按容器宽度排版 窄的时候头像在上、文字在下

当前：容器够宽 → 横排 当前：容器变窄 → 竖排

container-type: inline-size 会自动套上 layout 和 style 两种包含。容器查询不是另一个孤立特性，它就是 containment 的实际用途——先声明「这块独立」，浏览器才敢按它自己的宽度去算样式。

关键 CSS 
.cq {
    container-type: inline-size;  /* ← 同时带上 layout + style 包含 */
    resize: horizontal;            /* 拖右下角改宽度，方便观察 */
    overflow: hidden;
    width: 62%;
}

@container (max-width: 380px) {    /* 量的是容器宽度，不是视口 */
    .cq-card { flex-direction: column; }
}

content-visibility · 连渲染都跳过

content-visibility: hidden 会把内容整个跳过：不绘制、不进 tab 顺序、find-in-page 也搜不到。

这段内容在开关打开后会被浏览器「跳过」，而不是简单地隐藏。

跳过内容时会自动加上 layout、style、paint、size 四种包含，所以盒子连高度都没有了。

这个值适合做折叠面板的收合态。真正实用的是 auto：元素对用户不可见时跳过渲染，滚回来再补算，配合 contain-intrinsic-size 保住滚动条高度。长列表、长文章用它最划算。

关键 CSS 
.cv-host {
    content-visibility: hidden;  /* ← 整个跳过，连高度都没有 */
    /* 自动附带 layout / style / paint / size 四种包含 */
}

/* 长列表更常用这个：离屏才跳过，滚回来再补算 */
.post {
    content-visibility: auto;
    contain-intrinsic-size: auto 320px;
}

① content-visibility: hidden 只跳过内容，元素自身的背景和边框照常绘制——它看起来是个空壳。
② display: none 的 img 仍会下载（背景图不会）；content-visibility: hidden 里从未渲染过的图片不会被加载。

实际项目里怎么写

真实页面里几乎不会一处处手写 contain，多半是下面这几种固定用法。注意只有确定能自己给尺寸的块才敢用strict。

/* 最常见：独立的内容块，不含 size，可以放心大面积加 */
.article { contain: content; }

/* 手动给尺寸的块，才敢用 strict */
.fixed-panel {
    contain: strict;
    contain-intrinsic-size: 320px;
}

/* 容器查询：inline-size 自动带上 layout + style 包含 */
.card-list { container-type: inline-size; }

@container (max-width: 380px) {
    .card { flex-direction: column; }
}

/* 长列表：离屏跳过渲染，但要给占位高度 */
.post {
    content-visibility: auto;
    contain-intrinsic-size: auto 320px;
}
